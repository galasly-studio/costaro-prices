# COSTARO — массовая подготовка трёх уровней цен к ручной проверке

## Что будет работать после установки

Ежемесячная GitHub Actions проверка автоматически создаёт **два новых файла**:

1. `material_tier_review.json` — структура по всем 41 позициям материалов и всем 45 товарным группам, в том числе причины задержки каждой группы.
2. `material_tier_review_RU.md` — читаемая таблица кандидатов для уровней **Бюджет / Стандарт / Премиум**, скачиваемая вместе с другими отчётами из GitHub Actions → Artifacts → `costaro-monthly-market-check`.

Оба файла создаются **при каждом ежемесячном запуске** после сбора живых цен и аудита. Не требуется вручную обновлять список кандидатов после каждого сбора.

## Почему на старте именно шесть кандидатов

В исследовательском `price_sources.json` только **шесть конкретных товаров** уже имеют сохранённые подсказки `tierCandidateForReview`: три варианта финишной шпаклёвки 8 кг и три варианта краски 7 кг. Это **не утверждение качества** и не разрешённое ценовое соответствие. Остальные материалы нельзя профессионально делить на классы только по ценнику.

| Материал | Бюджет — изучить | Стандарт — изучить | Премиум — изучить |
|---|---|---|---|
| Финишная шпаклёвка, 8 кг | Meșterul Manole | B-62 SATROC | SATROC |
| Интерьерная краска, 7 кг | Romanița | Euroton LAV | Sansiro |

При корректных и свежих данных ожидается `Candidate product groups: 6` и `Complete three-tier sets for human review: 2`. **Оставшиеся 39 товарных групп** находятся на удержании до проверки уровня и/или доказательств.

## Защита от недостоверных данных

- Новые файлы строятся только при `material_update_policy.enabled: false` и пустом `approvedMappings`.
- Каждая товарная карточка сверяется с собственным `id` и исходными URL, магазином, артикулом и количеством наблюдений. Запрещены две карточки одного магазина или одного хоста вместо двух независимых источников.
- Проверяется давность наблюдений (не старше 24 часов), цены в MDL, положительность цен и расхождение не более 20% между магазинами.
- Медиана вычисляется из исходных наблюдений и отдельно сверяется с ценовым аудитом, чтобы не получить несогласованные отчёты.
- Для кандидатов с упаковкой в килограммах проверяется **точное** соответствие фасовке сметы. Не допускается пересчёт товара 20 кг в товар 8 кг.
- Не применяется никакая автоматическая оценка качественного уровня по одной только цене. Подсказки уровня требуют отдельного подтверждения характеристик материала.
- HTML-извлечение JSON-LD или видимого текста требует дополнительной проверки идентичности перед любой будущей публикацией.
- Обычный отчёт аудита (`COMPARISON READY`) не равен утверждению уровня и не равен разрешению менять каталог.

## Чего новый модуль НЕ делает

- Не изменяет `prices.json`, `app_embedded_baseline.json` и `material_update_policy.json`.
- Не меняет стоимость работ, расчёты и три уровня цен в опубликованном COSTARO.
- Не меняет Flutter-приложение и не публикует обновления цен.
- Не решает без пользователя, какой строительный материал «премиальный».

## Проверка

После установки и отправки в GitHub запустить **один раз** `COSTARO Monthly Market Check` из Actions. В новом шаге `Prepare budget standard premium manual review (read-only)` должны появиться показатели кандидатов, а в общем архиве — два новых отчёта.

Проверено локально без сети: `python3 -m unittest discover -s tests -q` — 98 тестов пройдены.
