# COSTARO — безопасная автоматизация цен, этап 01.11.2026

## Точный статус

**Автоматическое изменение цен для пользователей ещё НЕ включено.** Это
намеренная защита: текущий `prices.json` — `status: draft`, а
`automaticUpdatesEnabled: false`. Политика `material_update_policy.json`
в исходном репозитории не содержит утверждённых товарных соответствий.
Исследовательские «цены-кандидаты» не являются утверждёнными уровнями
**бюджет / стандарт / премиум**. Стоимость материалов и работ в уже
установленном приложении не меняется.

### Что добавлено в этот пакет

1. **Единая физическая проверка фасовок и единиц.** Планировщик теперь
   использует те же правила `exact`, что и независимый аудит. Поддерживаются
   только точные совпадения для кг, отдельных штук, м², метров, листов,
   профилей, рулонов и упаковок с известным количеством. Размеры,
   требующие пропорции или ручной конверсии, заблокированы.
2. **Жёсткий шлюз выпуска** `scripts/prepare_verified_catalog_release.py`.
   Он проверяет 41 материал и 37 видов работ, источники/артикулы, две
   независимые цены, сильный метод извлечения, свежесть до 24 ч,
   расхождение магазинов до 12%, изменение позиции 2–8%, диапазон ±30%
   относительно встроенного каталога, порядок трёх уровней и совместимость
   с приложением. Не меняет `prices.json`. При одобрении готовит
   `release_candidate/prices.json` с новой patch-версией.
3. **Подробный видимый отчёт** о готовности появляется в **Summary**
   ежемесячного запуска GitHub Actions. Его можно прочитать прямо в браузере,
   без скачивания **Artifacts**.
4. **Подготовленный, но ВЫКЛЮЧЕННЫЙ** шаблон полного издателя:
   `.github/workflows/approved-price-publisher.yml.disabled`.
   После всех подтверждений шаблон сможет ежемесячно проверять рынок,
   обновлять `prices.json` в GitHub и самостоятельно разворачивать
   проверенный JSON на GitHub Pages.
5. Регрессионные тесты проверяют безопасное поведение, включая реальные
   типы упаковок, недостоверные цены, отсутствие согласования и
   переход версии. Старые тесты сохраняются.

### Почему сейчас нельзя включать издатель

Необходимо **один раз**:

1. Проверить артикулы, качество и фасовки товаров и вручную решить, какие
   товары являются бюджетными, стандартными и премиальными. Равная цена или
   совпадающая фасовка не доказывает одинаковое качество.
2. Подтвердить каждое соответствие `catalogMaterialKey` + `tier` + `id`
   товара. Записать подтверждённые `priceTier` в `price_sources.json`,
   точные пары — в `material_update_policy.json` (`approvedMappings`).
   Нельзя присваивать уровни всем товарам автоматически.
3. Проверить **первый полный** каталог с 41 материалом/37 работами,
   установить `status: published`, `automaticUpdatesEnabled: true`
   **только после** соответствующей сверки с Flutter и реальными ценами.
   Шлюз выпуска не может сам превратить черновик в опубликованный каталог.
4. Проверить GitHub Pages: URL приложения
   `https://galasly-studio.github.io/costaro-prices/prices.json` должен
   открывать ровно ожидаемый полный JSON. В настройках Pages выбрать
   **Source: GitHub Actions**, прежде чем активировать издатель. Он
   публикует отдельный сайт ценового репозитория, заменяя его предыдущий
   сайт. Убедитесь, что в этом репозитории нет другой нужной страницы.
5. После этого осознанно установить в `material_update_policy.json`
   `enabled: true` и `automaticPublicationApproved: true`, включить
   подготовленный workflow, переименовав `.yml.disabled` в `.yml`.
   Пока соответствия не утверждены, обе настройки должны остаться
   выключенными.

Публикация через `GITHUB_TOKEN` **не запускает GitHub Pages branch build**.
Поэтому шаблон содержит отдельные официальные шаги
`upload-pages-artifact`/`deploy-pages`: они действуют внутри GitHub Actions,
**не требуют от пользователя скачивать Artifacts**. При защищённой ветке
`main` автоматическая запись может потребовать отдельных разрешений.

### Команды проверки в корне репозитория

```powershell
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/validate_app_catalog.py --catalog prices.json --baseline app_embedded_baseline.json
```

В ежемесячном запуске данные автоматически собираются и запускается
`python3 scripts/prepare_verified_catalog_release.py`. Пока действуют
ограничения, отчёт должен показать `status: held` и причины задержки.

**Не надо удалять, менять вручную или подменять опубликованные цены ради
зелёного статуса CI.** Безопасная задержка лучше ошибочной сметы.

## Следующий этап после установки пакета

Получить таблицу **ручного утверждения SKU → материал/уровень**, заполнить
только реально проверенные соответствия. Затем вместе проверить
первоначальный полный каталог и GitHub Pages. Только после этих проверок
разрешать активную публикацию. Рабочие ставки 37 видов в данный момент
**аудируются, но автоматически НЕ переписываются**: рыночных доказательств
и безопасных критериев для автоматической правки работ пока недостаточно.
