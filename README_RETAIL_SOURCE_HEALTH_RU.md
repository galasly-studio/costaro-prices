# COSTARO — диагностика и безопасное восстановление источников (01.11.2026)

## Что исправлено

Проверка GitHub от 01.11.2026 была успешной технически, однако результаты
показали массовую потерю текущих цен у Macons и Domic. Старый сборщик
скрывал категорию ошибки, поэтому невозможно было понять, заблокирован
ли доступ, пропала ли страница или перестал находиться проверенный товар.

Этот пакет **не пытается обойти ограничения магазинов**. Он:

- Пишет в отчёт безопасный код причины (`http_403`, `http_429`, `timeout`,
  `dns_error`, `tls_error`, `unexpected_content_type`,
  `product_identity_or_price_not_verified`, `multiple_possible_prices` и др.).
- После ответа HTTP 403 или 429 прекращает запрашивать остальные карточки
  на том же хосте до следующего запуска. Так мы не усиливаем блокировку
  десятками повторных запросов.
- Продолжает обработку независимых магазинов после отказа одного сайта.
- Добавляет `sourceHealth` в локальный `price_observations.json` и показывает
  понятную таблицу **прямо в GitHub Actions → Summary**, без скачивания
  Artifacts.
- Сохраняет весь прежний порядок проверки фасовки, SKU, свежести и цен.

## Чего пакет намеренно не делает

- Не изменяет `prices.json`, `price_sources.json`, политику публикации или
  расценки работ.
- Не подменяет отсутствующие цены устаревшими данными.
- Не пытается обходить HTTP 403/429, скрывать личность сборщика, применять
  прокси или загружать цены с непроверенных сайтов.
- Не объявляет `structured_data` достаточным доказательством для
  автоматической публикации без надёжной привязки к конкретному SKU.

## Как использовать результат

После отправки патча GitHub автоматически запустит `COSTARO Monthly Market
Check`. В Summary появится раздел **«Доступность магазинов — ошибки и методы
получения цен»**.

Если Macons/Domic отвечают `http_403` или `http_429`, это ограничение доступа
или интенсивности запросов, а не ошибка расчётов COSTARO. Нужно получить
доступ к официальному товарному фиду или согласовать допустимый источник,
либо подобрать независимые магазины с идентичным SKU и фасовкой.

Если отображается `product_identity_or_price_not_verified`, страница
доступна, но текущий HTML не подтверждает требуемые товар и цену: только
тогда имеет смысл корректировать парсер для данного сайта и расширять тесты.

Если преобладают `timeout`, `dns_error`, `tls_error` или `network_error`,
проблема в сетевом доступе и требует отдельной проверки.

Этот запуск остаётся **read-only**, статус исходного каталога — `draft`.
Для автоматического обновления после восстановления источников отдельно
потребуются человеческие подтверждения уровней бюджет/стандарт/премиум,
выпуск первого полного каталога и настройка GitHub Pages.
