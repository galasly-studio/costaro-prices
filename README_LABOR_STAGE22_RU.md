# COSTARO — этап 22: очередь проверки всех цен работ

Дата: 03.11.2026. Проект: `costaro-prices`. Изменения Flutter и опубликованных цен: **0**.

## Что добавлено

После успешного этапа 21 в отдельную безопасную проверку собираются **37** видов работ COSTARO и **один** самостоятельный этап стартовой шпаклёвки — всего **38** строк.

- `scripts/build_labor_review_queue.py` проверяет совпадение `prices.json`, точных правил, извлечённых наблюдений и отчёта отклонений. Если запись подменена, не соответствует заранее разрешённому правилу либо цена помечена разрешённой к публикации, задача завершается ошибкой.
- `labor_manual_research_leads.json` содержит **5 направлений ручной проверки** для трёх пока неохваченных автоматическим сопоставлением работ. Это **ссылки и технологические ограничения, без чисел и цен**.
- `labor_manual_review_queue.json` создаётся при каждом запуске, сортирует задания по приоритету, сохраняется среди артефактов и отображается в GitHub Actions Summary.
- `tests/test_build_labor_review_queue.py` проверяет полноту очереди, запрет публикации, проверку домена, единицы измерения, запрет числовых расценок внутри подсказок и согласованность предыдущих двух отчётов.

## Три пробела, которые нельзя заполнять догадкой

| Работа в COSTARO | Сведения для ручной проверки | Почему нет автоматической цены |
|---|---|---|
| `removeDecorativeWork` — удаление декоративного покрытия | `euroremontstyle.md`: «Очистка стен от декоративной краски» | Декоративная краска и фактурная/минеральная штукатурка требуют разных технологий. |
| `floorRemoveOtherWork` — удаление прочего напольного покрытия | `euroremontstyle.md`: демонтаж паркета; `topmaster.md`: снятие приклеенной битумом подложки ДВП | Общая категория объединяет разные материалы и способы снятия. Нельзя назначать одну стоимость по цене паркета или подложки. |
| `vinylWork` — укладка винила | `tsgate.pereflex.md`: отдельно плавающая/замковая и клеевая укладка | Разный способ монтажа и подготовка основания; страница при внешнем исследовании могла отвечать ошибкой 502, доступность необходимо проверить. |

Адреса предназначены для ручного исследования. Они **не** включаются в сетевой сборщик цен, не вводятся как проверенные рыночные тарифы и не попадают в активный каталог. Автоматическое утверждение бюджет/стандарт/премиум запрещено.

## Как формируется очередь

Каждая работа получает ровно одну приоритетную группу. Приоритеты:

1. Нет точной настройки работа × сайт — нужна проверка технологии.
2. Единица измерения не совпадает или возник подозрительный выброс — проверить вручную.
3. По настроенному правилу нет полученной точной строки — проверить сайт/разметку.
4. Есть цена, но не совпадает или не подтверждён состав работ.
5. Недостаточно двух независимых ограниченных по диапазону предложений.
6. Есть два предварительно сопоставимых источника, но тариф, дата, уровень и технология всё равно не подтверждены.

Каждый элемент содержит `priceDateVerified: false` и `approvedForPublication: false`. Итоговые поля `publishedPricesChanged`, `flutterCalculationsChanged`, `automaticLaborPublicationEnabled` всегда `false`.

## Проверки после установки

Из корневого каталога репозитория выполнить:

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
```

Запускаемый в GitHub Actions порядок: `collect_live_labor_quotes.py` → `audit_live_labor_drift.py` → `build_labor_review_queue.py`. При отказе источника ожидается статус неуспешного исследования этой строки, но не подстановка цены из другого объявления. Сохранённые цены остаются без изменений.

После успешного зелёного workflow открыть раздел **«Очередь проверки 38 расценок»**. Следующая предметная задача — согласовать конкретный вид декоративного покрытия, прочего настила и способа укладки винила. Только после этого можно оформлять точные исследовательские правила без автоматической публикации цен.
